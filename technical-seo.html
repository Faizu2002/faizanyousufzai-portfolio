Technical SEO audit: the checks that come first

I start with the pages the business actually needs Google to discover. A technical audit should distinguish a sitewide problem from an individual URL and avoid treating every warning as a ranking emergency.

  1. Access: test the preferred URLs, HTTP status codes, robots rules and whether important content is available in the rendered page.
  2. Index selection: compare declared canonicals, redirects and Google Search Console's indexing reports. A URL can be technically indexable without Google choosing to index it.
  3. Site discovery: follow crawlable internal links from the homepage and relevant hubs. Compare those paths with the XML sitemap.
  4. Page signals: review titles, primary headings, duplication, structured data and mobile page experience.
  5. Validation: document the exact URL, evidence, suggested fix and result after implementation or recrawling.

Example: a service page that Google has discovered but not indexed

If Search Console reports Discovered – currently not indexed, I do not immediately change the URL slug. I verify whether the URL returns a 200 response, has a self-referencing canonical, is linked from relevant indexed pages and serves substantial unique content. I also compare recent Googlebot requests when server or CDN logs are available. If Google has not fetched the page, content-quality rejection cannot be established from that inspection status alone.

For Crawled – currently not indexed, I place more weight on comparing the rendered content, duplication and the pages Google already selected for similar intent. Indexing in SEO explains those different states, while the canonical guide covers preferred URLs.

What you receive after a technical SEO review

A usable deliverable is a prioritized URL-level fix list—not a screenshot of a tool score. Each issue includes a reproducible observation, likely impact, recommendation, owner and validation method. Where the stack allows it, I can implement HTML, CSS, JavaScript, metadata and internal-link fixes, then check that the change actually shipped. Core Web Vitals work is planned around real field data where available; a single Lighthouse score is not a guarantee. To understand which software answers which audit question, use the SEO tools box guide before paying for overlapping reports.

Is an XML sitemap enough to get every page indexed?

No. Sitemaps support discovery, but Google decides when to crawl and whether to index a URL. Important pages also need crawlable links and a purpose worth showing in search.

Do I need a full site rebuild for technical SEO?

Usually not. Many issues can be resolved by correcting templates, redirects, links, assets or directives in the existing build.

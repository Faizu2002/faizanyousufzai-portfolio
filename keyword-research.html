Keyword Research

Keyword research that turns search demand into a clean page map.

Keyword research is not a list of phrases to place in content. I use it to understand demand, separate search intents, decide which URL should own each topic and find gaps that fit the website.

Start with topics, not thousands of exports

Large keyword exports contain duplicates, noisy suggestions and terms that belong to other topics. I first define the main SEO entities and problems, then clean and group the data.

A keyword is useful only when it helps decide what page to create, improve or avoid.

Give each intent one clear page owner

Several keywords can belong to one page when they ask for the same thing. Creating a new URL for every wording variation can split signals and create cannibalization. Location-based service queries also need place and proximity context; see local keyword research for that narrower task.

I map a primary intent to one URL, then use closely related terms to shape sections, examples and FAQs instead of multiplying pages.

Prioritize with more than search volume

Volume can help, but relevance, difficulty, business value, current rankings and how well the topic supports the wider site all matter. A smaller query can be a better next page if it completes an important cluster.

This is especially useful for a growing site because it builds topical depth while still finding realistic opportunities.

My keyword research workflow

I begin with the website, services and existing search visibility before opening a keyword tool. Seed terms are expanded with relevant variations, competitor gaps and questions, then cleaned so unrelated suggestions do not distort the plan.

The next step is intent grouping. Keywords that lead to the same useful answer usually belong to one page, even when the wording is different. I separate informational, commercial and local intents when they need different page types, then assign one clear URL owner to each cluster.

How I reduce keyword cannibalization

Before creating a page, I check whether an existing URL already targets the same intent. If it does, improving that page is usually safer than publishing another version. This is especially important for broad topics such as SEO strategy, content SEO, local SEO and technical SEO where many related phrases can look different in a spreadsheet but mean almost the same thing.

After mapping, I prioritize clusters using relevance, realistic difficulty, search demand, business value and how well the page strengthens the wider topic. What a keyword research service should deliver

The deliverable is a page and priority decision, not a huge export of phrases. Research should show which searches are commercially useful, which URL is best placed to satisfy each intent, and what a business can realistically improve first.

  • Seed topics: start from products, services, audience problems and the actual market.
  • Query groups: organize synonyms and variations by what a searcher expects to see.
  • Page ownership: map each meaningful intent to an existing URL, a proposed new URL or a page that should be consolidated.
  • Competitor review: compare competing page types and content depth for the same geography and intent.
  • Prioritized roadmap: recommend refreshes, missing service pages and supporting articles, with the reason for each decision.

Example: mapping keywords to pages without cannibalization

Consider a website offering website audits. Technical SEO audit service and hire SEO auditor may belong on a commercial SEO audit service. Technical SEO checklist belongs in an instructional guide, while SEO audit template can lead to a practical downloadable resource. Splitting these intents helps users reach the right page and prevents publishing several near-identical sales pages.

Volume is one input, not the whole decision. A lower-volume query that strongly matches a service can matter more to the business than a broad query that attracts people who will never enquire. I review keyword difficulty estimates carefully because they are third-party models, not Google's own ranking scores.

My keyword research workflow

Discover: collect queries from Search Console, the website and competitive research. Qualify: remove irrelevant intent and misleading search volume. Cluster: group phrases based on the likely answer and actual search results. Map: select a single primary destination for each distinct intent. Review: validate the page structure and measure query/page performance after publishing.

Should I create a new article for every keyword variation?

No. Phrases that mean the same thing normally deserve one useful page. Publish separately only when search intent or the required answer differs meaningfully.

Can keyword research help an already indexed website?

Yes. Existing impressions can reveal pages Google already considers relevant. Refining those pages is often the first step before making more URLs.
